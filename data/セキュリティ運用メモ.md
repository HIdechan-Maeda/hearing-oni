# セキュリティ運用メモ（2026-05）

このメモは、今回反映した Supabase / アプリ側のセキュリティ対策を再現・確認するための手順です。

## 1) 反映済みの主な対策

- 問題テーブル `questions_core` を **ログイン必須**に変更（`anon` の読み取り不可）
- 教師判定関数を `public.is_teacher()` から **`private.is_teacher()`** へ移行（Linter 0029 対応）
- `profiles.role` を DB トリガーで保護し、**自己昇格（teacher化）不可**
- 新規登録を `/api/signup`（サーバー側 allowlist 判定）へ統一
- ランキング RPC（`leaderboard_cohort` / `leaderboard_affiliation`）を **SECURITY INVOKER** に変更

## 2) SQL の実行順（新環境セットアップ時）

最低限、次の順で SQL Editor で実行してください。

1. `data/SUPABASE_RLS_profiles.sql`
2. `data/SUPABASE_profiles_protect_role.sql`
3. `data/SUPABASE_RLS_questions_core.sql`
4. `data/SUPABASE_fix_is_teacher_private_schema.sql`
5. `data/SUPABASE_fix_leaderboard_security_invoker.sql`

必要に応じて追加:

- `data/SUPABASE_signup_allowlist.sql`
- `data/SUPABASE_announcements.sql`
- `data/SUPABASE_RLS_questions_core_tags.sql`
- `data/SUPABASE_RLS_students.sql`
- `data/SUPABASE_RLS_student_progress.sql`
- `data/SUPABASE_RLS_measurements.sql`

## 3) Vercel 環境変数（必須）

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`（`/api/signup` で必須）
- `OPENAI_API_KEY`（教師向け問題生成を使う場合）

補足:

- 環境変数を変更したら Vercel で再デプロイ
- `SUPABASE_SERVICE_ROLE_KEY` が無いと新規登録 API は 503 になる

## 4) Supabase 設定チェック

- Dashboard -> Settings -> API -> Exposed schemas に `private` を入れない
- Database Linter で以下が解消していること
  - `is_teacher` の SECURITY DEFINER 警告
  - `leaderboard_*` の SECURITY DEFINER 警告

## 5) 動作確認チェックリスト

- 未ログイン状態:
  - 問題（`questions_core`）を直接取得できない
- 学生ログイン:
  - セッション / 復習 / ランキング（自分の所属・学年範囲）が動作する
- 教師ログイン:
  - 教師ダッシュボード / お知らせ / 許可リスト / ランキングが動作する
- 新規登録:
  - 学内メールまたは allowlist のみ通る
  - 許可外メールは拒否される

## 6) よくあるエラーと対処

- `cannot drop function is_teacher() because other objects depend on it`
  - `data/SUPABASE_fix_is_teacher_private_schema.sql` を最新内容で全文再実行
- `relation "public.measurements" does not exist`
  - テーブル未作成環境。最新の `data/SUPABASE_fix_is_teacher_private_schema.sql` は存在チェック付き
- `next build` の TypeScript エラー
  - まずローカルで `npm run build` を実行し、失敗箇所を確認してから再 push

## 7) 運用ルール（推奨）

- 教師権限付与は管理者のみ（Dashboard または SQL）
- SQL 実行後は Linter と主要画面を必ず確認
- セキュリティ系 SQL を更新したら、このメモも更新する
